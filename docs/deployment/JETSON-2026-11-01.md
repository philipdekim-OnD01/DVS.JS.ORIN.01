# Jetson DVS 설치 및 RAW2 실시간 표시 기록

최종 확인일: 2026-11-01 (Asia/Seoul). 대상: `philip@192.168.0.121`.

## 결과

드라이버, CAM1 overlay, SDK, RAW2/GROUP AER 디코더 및 `dvs_streamer`를 빌드했다.
드라이버/overlay 설치 후 사용자가 전원을 껐다 켰고, 실제 로드 및 `/dev/video0` 생성을 확인했다.
이후 RAW2 센서 수신과 디코딩을 시작해 PC 웹 뷰어에서 이벤트 영상이 갱신되는 것을 확인했다.
Jetson의 로그인된 데스크톱에도 Firefox로 로컬 뷰어를 열었고 창 제목을 확인했다.

- PC: <http://192.168.0.121:8080/>
- Jetson: <http://127.0.0.1:8080/>
- 센서 영상 크기: 960×720. 회색 배경, ON 흰색, OFF 검정.
- 관찰 화면: 회색 배경 위 변화 이벤트 점들이 표시됨. 정적인 RGB 영상이 아니므로 물체/조명 변화로 확인한다.
- 약 1,600 decoded frames/s, 웹 화면 약 50–60 FPS. UI의 1,603 FPS는 미교정 센서 시각 **후보**이며 교정된 측정값으로 취급하지 않는다.
- 녹화는 시작하지 않았다. 재부팅 시 수신기를 자동 실행하는 서비스도 새로 등록하지 않았다.
- GROUP AER 코드는 빌드됐지만 이번 하드웨어 수신 검증은 RAW2로만 수행했다.

## 1. 최초 환경 확인 — 2026-10-29

처음 장치는 Orin Nano Super, Ubuntu 22.04.5, Jetson Linux R36.4.3,
커널 `5.15.148-tegra`, GCC/G++ 11.4.0, CMake 3.22.1이었다.

PC의 기존 Git 인증으로 main을 복제했다. Jetson의 직접 private clone은 인증 부재로 실패하여
Git bundle을 SSH로 전송했다. 토큰이나 개인키는 Jetson에 저장하지 않았다.
필수 소스 15개, Git 객체 무결성 및 실행 권한을 확인했다.

`./build.sh all`은 고정 커널 불일치 검사에서 중단했다. `./build.sh app`은 preset 버전 오류,
C++20 probe는 `<format>` 헤더 부재로 실패했다. 커널 검사나 소스를 우회하지 않았다.
독립적인 DTBO 컴파일 및 기본 DTB 오프라인 병합만 성공했다.
당일에는 커널/JetPack/부팅 설정을 변경하거나 모듈을 설치하지 않았다.

증거: [초기 환경과 실패 로그](evidence/2026-10-29/).

## 2. 재설치된 Jetson 환경 확인 — 2026-11-01

OS 재설치는 이 작업에서 수행하지 않았으며, 재접속 시 다음 환경을 확인했다.

| 항목 | 확인값 |
|---|---|
| 보드 | NVIDIA Jetson Orin Nano Engineering Reference Developer Kit Super |
| OS / CPU | Ubuntu 24.04.4 LTS / aarch64 |
| Jetson Linux | R39.2.1 |
| nvidia-l4t-core | 39.2.1-20260806224157 |
| 커널 | 6.8.12-1021-tegra |
| GCC/G++ | 13.3.0 |
| CMake | 3.28.3 |
| 소스 커밋 | 04908bb3511f0c224da2953ffbba0d0d0fb4d700 |

커널과 NVIDIA `Module.symvers` SHA-256이 `bsp/r39.2.1/manifest.env`와 정확히 일치했다.
재설치 후 기존 SSH 공개키 인증은 거부되어 사용자 제공 인증으로 대화형 SSH를 사용했다.
인증 비밀은 파일/로그/이 문서에 기록하지 않았다.

## 3. 소스 전송과 빌드

PC에서 main 최신 커밋을 확인한 뒤 Git bundle을 전송하고 Jetson 홈에 복제했다.
origin은 `https://github.com/philipdekim-OnD01/DVS.JS.ORIN.01.git`으로 설정했다.

Jetson에서 실행한 주요 명령:

```bash
sudo apt-get update
sudo apt-get install -y --no-install-recommends \
  g++ make cmake ninja-build python3 curl device-tree-compiler kmod bzip2 libzstd-dev
cd ~/DVS.JS.ORIN.01
git fsck --full
set -o pipefail
JOBS=4 ./build.sh all 2>&1 | tee build/logs/all-install.log
```

`BUILD_EXIT=0`. 공식 NVIDIA public sources(309,583,176 bytes) 및 내부 OOT 아카이브의
SHA-256 검증을 통과했다. 다운로드한 NVIDIA 소스와 컴파일 산출물은 Git에 포함하지 않았다.

| 산출물 | 크기(bytes) |
|---|---:|
| build/nrv_dvs.ko | 127056 |
| build/cam1.dtbo | 4950 |
| sdk/build/GCC-arm64/Release/lib/libnrv_dvs.so.0.1.0 | 199280 |
| app/dvs_streamer/build/GCC-arm64/Release/dvs_streamer | 133136 |

Module vermagic: `6.8.12-1021-tegra SMP preempt mod_unload modversions aarch64`.
Streamer는 AArch64 ELF이며 `ldd`에서 모든 의존성이 해석됐다.
SDK/Streamer는 저장소의 빌드 경로를 사용한다. 시스템 전역 SDK 설치는 하지 않았다.

커널 빌드 GCC 13.2와 현재 GCC 13.3의 차이 경고 및 DTS 구조 경고가 있었지만 빌드는 성공했다.
누락된 `raw_max_sensitivity.bin`은 내부 벤치마크 데이터이며, 이번 tests=OFF 빌드와 라이브 수신에
필요하지 않았다. 빈 파일이나 가짜 코드로 대체하지 않았다.

## 4. 검증 및 설치

```bash
python3 tests/checks.py modules "$PWD"
./tests/check-build.sh
scripts/boot-setup.sh check
scripts/boot-setup.sh install --dry-run
sudo scripts/boot-setup.sh install
```

드라이버의 full vermagic 및 NVIDIA 카메라 import 9개 심볼의 CRC 일치,
기본 보드 DTB와의 overlay 병합, boot check, 설치 dry-run을 확인했다.
설치 명령은 exit 0이었다.

종합 검사 전체는 성공으로 표시하지 않는다. 다음 오래된 검사 때문에 exit 1이다.

- `ac3-modules`: 위임용 `app/run.py` 자체에 `--settings` 문자열을 요구하는 정적 검사 1건 실패.
  실제 새 runner는 옵션을 처리하여 setfile을 Streamer에 전달하며, 센서 레지스터 적용도 확인했다.
- `ac5-app`: 과거 `build/dvs_live`를 요구해 실패. 현재 실행본은 `dvs_streamer`다.
- `ac4-overlay`, `ac7-scan`: 통과. `ac4-compare-dt`: 과거 기준 DTB 부재로 실제 비교 생략.

이 불일치 때문에 원본 검사나 실행 파일을 임의 수정하지 않았다.

설치 위치 및 변경 사항:

- `/lib/modules/6.8.12-1021-tegra/updates/nrv/nrv_dvs.ko`
- `/etc/depmod.d/nrv-dvs.conf`, depmod 재생성
- `/boot/nrv-dvs/cam1.dtbo`, `/boot/nrv-dvs/install.state`
- extlinux에 `nrv-dvs` 항목 추가 및 `DEFAULT nrv-dvs`, 기존 `primary` 보존
- 백업: `/boot/nrv-dvs/backup/extlinux.conf.20261101-115409`
- NVIDIA stock `tegra-camera.ko` 유지. 실행 중 강제 모듈 교체/언로드 없음.

설치본과 빌드본의 `cmp` 및 SHA-256 일치:

```text
nrv_dvs.ko d2224c7d0089398d0fca75216e786a355bdc8ba2618e8cf331277f145a774198
cam1.dtbo  6a7e74e0d524f3c06549615423f6b9c6be0458eef3291b44d16f39a8c9b0b15b
```

## 5. 전원 재인가 후 확인

사용자 전원 재인가 후 SSH 로그인과 데스크톱 자동 로그인 완료를 확인했다.
`scripts/boot-setup.sh status`는 overlay 적용, 실행 중 DVS 모듈 build-id 일치,
stock NVIDIA 모듈 유지 및 `/dev/video0`를 확인해 `status: ready`를 출력했다.
당시 모니터 연결과 GNOME/Xorg 실행도 확인했으며 화면 설정은 변경하지 않았다.

커널 로그에는 `DVS ready: I2C readback wrote=0x55 read=0x55; silicon ID not verified`가 있다.
따라서 I2C readback 성공과 silicon ID 확인을 구분한다. 자체 빌드 모듈의 서명 키 부재로
kernel taint 메시지도 기록됐다. 이번 부팅에서는 모듈 로드가 성공했다.

## 6. RAW2 디코딩 및 화면 표시

현재 사용자는 video 그룹에 속한다. numpy, PyYAML, Pillow 및 fuser가 이미 설치돼 있었고
import 검사가 통과했다. 필요 시 패키지 이름은 다음과 같다.

```bash
sudo apt-get install python3-numpy python3-yaml python3-pil psmisc
```

실제 실행:

```bash
cd ~/DVS.JS.ORIN.01
./dvs status
./dvs start
curl -fsS http://127.0.0.1:8080/stats.json
```

기본 setfile은 `Delta_10_2000FPS_RAW2.txt`이며 커널 로그에서 100개 register write 적용을 확인했다.
`capture=25104`, `viewer=25105`로 시작했다(당시 PID이며 다음 실행에서 달라진다).
관찰된 GUI 환경을 사용해 Jetson Firefox에서 `http://127.0.0.1:8080/`를 열었다.
PC 브라우저에서는 실제 화면과 실시간 수신 표시를 시각적으로 확인했다.

| 실행 경과(s) | 버퍼 | 디코딩 프레임 | 이벤트 | dropped / starved / error_buffers |
|---:|---:|---:|---:|---|
| 16.448 | 26247 | 26272 | 27597030 | 0 / 0 / 0 |
| 44.822 | 71538 | 71610 | 71408433 | 0 / 0 / 0 |
| 77.011 | 122915 | 123040 | 121653728 | 0 / 0 / 0 |

모든 샘플은 동일 session_pid, `format=raw2`, `has_frame=true`, `last_good_age=0`였다.
카운터 증가를 확인했으며 HTTP 성공이나 `state=live`만으로 수신 성공을 판정하지 않았다.
`invalid`, `raw2_short_frames`는 0이었다. 마지막 샘플의 `raw2_timestamp_ambiguous=13`,
`raw2_timestamp_order_errors=1`은 남은 시각 해석 이슈로 기록한다.
실시간 우선순위 권한이 없어 일반 우선순위로 실행됐고, 관찰 구간의 starved는 0이었다.
장시간/고부하 안정성과 센서 시각 정확성까지 검증한 것은 아니다.

증거: [빌드·설치 로그](evidence/2026-11-01/build-install/),
[수신 통계·실행 로그](evidence/2026-11-01/runtime/).
센서 원시 데이터, 프레임 이미지, 비밀번호, 개인키 및 NVIDIA 소스는 이 Git 기록에 포함하지 않는다.

## 다시 사용하기

```bash
cd ~/DVS.JS.ORIN.01
./dvs status             # 현재 수신기 확인
./dvs start              # 실행 중이 아닐 때만 시작, sudo 사용 금지
./dvs stop               # 수신과 웹 뷰어 종료
scripts/boot-setup.sh status
```

브라우저를 닫아도 수신은 계속된다. 중지하려면 `./dvs stop`을 사용한다.
이번 작업 종료 시 수신기와 뷰어를 실행 상태로 남겼다.
